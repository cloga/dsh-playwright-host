# Repository agent rules

- Use the exact `cloga` GitHub identity for every write.
- Load credentials into the current process only from a user-designated trusted `.env`; never print or commit them.
- Keep Issue → `cloga-<task-slug>` branch → verification → pull request → merge → sync.
- Never push directly to `main`.
- Keep Microsoft Playwright MCP pinned and update the Windows Ops practice in `cloga/dsh-windows-ops` whenever installation, lifecycle, security, or compatibility guidance changes.
- Version `0.1.6` adds source-seam certification for DSH Core `0.1.5-rc.2` at commit `fb2c4b9e698e30edb738bca4cf0618587db7d203` and DSH Core `0.1.5-rc.1` at commit `183f08e9c6dde7e36cd2318eaee70b0da08fb35e`, retaining DSH Core `0.1.5-alpha.2` at commit `b2e3b2a0125854567a4a5fcba75782e42fe84901`, DSH Core `0.1.5-alpha.1` at commit `5dda764ed3aa172535a7967b06ff95d9cbfe536a`, official DSH `0.1.2-rc.1` at commit `a66e4702047846cdaa10c66c9d3df3951f5ea70d`, and DSH Core `0.1.3-alpha.1` at commit `d347e703908d0406b7a7ef80e3a0e594d86b2215`. Run `npm test` for every pair using either `DSH_CORE_PATH` at its exact source checkout or `DSH_CORE_PATH` at an existing repository plus `DSH_CORE_REF` set to the full certified commit. The optional ref mode reads Git objects only; do not create or switch Core worktrees just for these source checks.
- Version `0.1.7` additionally certifies upstream DSH `0.1.6-alpha.1` at commit `0a15e36e7f82b6ed45af6fa9759f29b40dcd965d` and tree `66c4c9c2053c6fcf91ad4e47d85bd77539c0b101`. The CI contract job must run the exact upstream MCP SDK v2, resource, lifecycle, profile-composition, pagination-isolation, and native/PTC resource tests; source markers alone are insufficient for this source.
- cloga/deepseek-harness#33 has merged with green CI. Keep `0.1.7` blocked from merge and release while the current `0.1.5` Desktop prerelease is `immutable:false`, its publish job is failed, and the remote managed Check is skipped; require a corrected release, the Windows Ops `0.1.5` repin, and explicit cloga/dsh-windows-ops#161 clearance.
- The alpha.1 → alpha.2 MCP production code change only rejects repeated non-empty `tools/list` continuation cursors in `syncTools`; it does not change the config/API consumed by this bundle. The alpha.2 → rc.1 → rc.2 production source diff is empty, so the same guard markers hold for both rc sources. Keep that source-marker check conditional on the three cursor-guarded sources; do not reinterpret it as a functional pagination test.
- Source versions are not publication evidence: a version in `package.json` declares intent, and only the Release artifacts prove publication. Merging a version bump to `main` publishes it — the caller gates on the whole certification matrix, `release.yml` creates the annotated version-matching tag on that verified revision itself, and an already-tagged version publishes nothing. Never push a release tag by hand, and delete a tag left behind by a failed run before retrying that version. Repository-level immutability must still be independently confirmed.
- Source-seam certification must accept only an explicitly certified commit/version pair and assert the root and `@deepseek-ai/dsh-mcp-client` versions plus every stdio config and lifecycle source marker consumed by `cordis.patch.yml`. Do not describe marker checks as runtime behavior tests. Windows CI owns runtime applicability; Linux may certify only the platform-neutral source seam.
- Preserve the shared MCP-process caveat: `--isolated` protects the personal browser profile but does not isolate concurrent DSH Sessions from each other.
- Never restart a live DSH Host without direct user authorization after checking for active Sessions.
